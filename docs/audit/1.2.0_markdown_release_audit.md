## Historical Material Policy

Old version numbers are not defects when they identify the release actually
tested, released, audited, or discussed. The audit therefore did not globally
replace version strings. It classified files by role:

- Active guides and landing pages: current published and upcoming release
  state must be explicit.
- Dated validation/audit/release records: preserve the original version and
  date; add historical framing only where readers could mistake status language
  for current guidance.
- Append-only logs and task briefs: preserve original text.
- Wiki synthesis: current pages must reflect the latest code/evidence; release-
  specific historical pages keep their original scope and receive a historical
  status in the index.
