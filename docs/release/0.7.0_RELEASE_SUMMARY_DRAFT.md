# 0.7.0 Release Summary Draft

Status: RC-candidate ready, not yet tagged or published

Stable published line:
- `0.6.3`

Planned release line:
- `0.7.0`

## Summary

`0.7.0` is the hardening release that consolidates the post-`0.6.3` work into a release candidate with stronger regression coverage, better Rust/C# parity, improved batch behavior, clearer unsupported/firmware-limited semantics, and real-hardware validation on both CompactLogix and ControlLogix.

## Highlights

- Rust and C# wrapper parity improved for:
  - batch read/write/execute
  - tag-group polling APIs
  - subscriptions
  - route-path usage
  - structured diagnostics and failure reporting
- Native batch-read behavior in the C# wrapper now uses the Rust/FFI path instead of only wrapper-side sequential probing.
- CompactLogix BOOL batch decoding was fixed in the native multiple-service path.
- Invalid subscriptions now fail fast instead of succeeding and dying later in background polling.
- Hardware-backed validation and benchmark baselines were recorded for:
  - CompactLogix `5069-L320ERMS3`, firmware `35`
  - ControlLogix `1756-L81ES`, firmware `37`, via `1756-EN3TR`, slot `0`

## Validated Real-PLC Scope

Validated in both Rust core and C# wrapper:
- connect/disconnect
- direct and routed connections
- primitive reads and writes
- program-scoped tags
- batch read/write
- mixed execute batches
- subscriptions and tag groups
- health checks
- array element addressing
- UDT reads and nested member/array access

## Known PLC/Firmware Limits

These are documented controller limitations, not current library regressions:
- direct writes to standalone `STRING` tags can fail
- direct writes to `STRING` members inside UDTs can fail
- direct writes to UDT array element members can fail

Observed forms on validated hardware:
- `0x2107`
- batch-level `0x1E` embedded service error for some direct STRING write paths

Recommended pattern:
- read-modify-write the full UDT or UDT array element instead of directly writing nested restricted members
