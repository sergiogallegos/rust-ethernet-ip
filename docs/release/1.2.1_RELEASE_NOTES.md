# rust-ethernet-ip v1.2.1

Published 2026-08-22. A backwards-compatible patch release collecting the
fixes merged after `v1.2.0` plus a substantial documentation,
hardware-validation, and project-website improvement. The Rust public API
remains compatible.

**C FFI ABI note:** the ABI version moves to **3** — additive over `1.2.0`'s
v2. The new `eip_refresh_schema` export and `CAP_SCHEMA_REFRESH` capability
bit are the only change; no existing export changed shape, and all shipped
wrappers (C#, Python, C++) pin the same ABI and expose the refresh operation.

## Code and Toolchain Changes Since 1.2.0

- Program-scoped Symbol Object discovery now continues after CIP `0x06`
  partial-transfer responses instead of losing programs with paged symbol
  tables.
- Program tag discovery now assigns the requested program scope to every
  returned tag. Both `Dashboard` and `Program:Dashboard` normalize to
  `TagScope::Program("Dashboard")`.
- The workspace MSRV is corrected from Rust 1.96 to Rust 1.88, verified against
  the locked dependency graph, workspace tests, and rustdoc.
- The desktop example now uses `egui`/`eframe 0.33.3` and `webbrowser 1.2.2`,
  removing `RUSTSEC-2026-0257` while preserving the Rust 1.88 baseline.
- C# batch writes now distinguish the program-scope separator in
  `Program:<program>.<tag>` from a UDT-member separator, so program-scoped
  scalar and array-element paths reach the native batch implementation.
- Repeated batch reads now cache both packed-BOOL and ordinary-array
  classifications per connection. The cache is shared across FFI client clones
  and scoped to a clone-shared schema generation. The new Rust
  `refresh_schema()` operation and route changes invalidate tag metadata, UDT
  definitions/templates/attributes, and array classifications together;
  generation guards prevent stale in-flight requests from refilling caches.
- Array reads now validate cached packed-BOOL addressing against controller
  responses. A stale read classification is evicted and rebuilt once, including
  inside a native batch without disturbing unrelated results. Write recovery
  remains fail-closed: a write is never replayed after an ambiguous outcome.
- Rust, C, C#, Python, and C++ now share an explicit schema-refresh workflow
  and expose the same schema/cache/recovery diagnostics. The additive native
  export is coordinated as C ABI v3 with a feature-detection capability bit.
- Fixed `get_tag_attributes`/`get_udt_definition` failing outright on
  controllers that reject the per-tag CIP Get Attribute List request (observed
  on a real ControlLogix 1756-L75 for every tag shape). The affected calls now
  fall back to the already-working bulk discovery sweep.
- Python `write_tags()` now uses native Multiple Service Packet batching for
  safe atomic scalars and numeric array elements while preserving ordered typed
  fallbacks for STRING/custom STRING, UDT, member/bit, packed BOOL element, and
  duplicate-name writes. Native throughput now matches Rust/C#/C++.
- CI and release workflows now use Node.js 24-native first-party GitHub Action
  majors instead of relying on GitHub's Node.js 20 compatibility shim.

## Documentation and Adoption

- Public API documentation now covers every item in `rust-ethernet-ip` and the
  `types`, `tag-path`, `protocol`, and `udt` support crates. A permanent
  `missing_docs` deny gate prevents regression.
- The real-hardware compatibility matrix identifies exact CompactLogix and
  ControlLogix processors, firmware, routes, bindings, test dates, and source
  evidence without generalizing one result to a whole family.
- Contributors now have a safe test-controller setup, cross-binding functional
  procedure, 24-hour endurance profiles, performance metrics, and a standard
  validation-result template.
- A restore-safe four-language companion gate measures batch operations,
  whole-UDT reads, controller discovery, and Rust program discovery separately
  from the full-tag inventory gate; unavailable wrapper surfaces are reported
  as `N/A`.
- The four full-coverage runners now include an explicit-write, release-build
  benchmark mode with per-call latency distributions and JSON output.
- A new project website (`website/`) ships with a responsive light theme,
  quick starts for Rust/C#/Python, direct links to docs.rs/crates.io/NuGet/
  PyPI, and concise real-hardware proof points.

## Real-Hardware Validation

Live-validated on ControlLogix `1756-L75/B`, firmware `33.011`, through a
`1756-EN2T/D` bridge:

- **Schema-change gate**: online array-shape swap (`DINT[64]` ↔ packed
  `BOOL[64]`, both directions, controller and program scope, indices below
  and above the packed-BOOL DWORD boundary) and offline UDT layout-edit +
  download, all four bindings, session survived every edit without
  reconnecting. See
  [`docs/validation/2026-08-22_1756-L75_fw33_schema-change-gate.md`](../validation/2026-08-22_1756-L75_fw33_schema-change-gate.md).
- **Post-merge full-coverage rerun**: 2,304/2,304 reads, 2,285/2,285 writes
  and read-back verifies, 2,285/2,285 settle operations, 0 anomalies, all
  four bindings. See
  [`docs/validation/2026-08-22_1756-L75_fw33_post-BF-BI-cross-binding-full-coverage.md`](../validation/2026-08-22_1756-L75_fw33_post-BF-BI-cross-binding-full-coverage.md).
- **Post-merge performance rerun**: zero failures across the full 2,304-tag
  sequential matrix (27,648 reads, 27,420 writes) and native DINT batch sizes
  1–100; all four bindings converge within ~0.08 ms average read latency and
  ~0.04 ms average write latency at size 100 (3,261–3,269 read tags/s,
  2,793–2,796 write tags/s). Python's native batch-write path now matches
  Rust/C#/C++. See
  [`docs/validation/2026-08-22_1756-L75_fw33_post-BF-BI-cross-binding-performance.md`](../validation/2026-08-22_1756-L75_fw33_post-BF-BI-cross-binding-performance.md).

## Known Limits

Unchanged from `1.2.0`:

- A single string read/write must fit one CIP packet unless the fragmented
  path applies.
- Whole-UDT array-element writes as a single structure are not supported —
  update members individually. Whole-element reads work (fragmented when
  large).
- `read_tag` returns custom string types as `PlcValue::Udt`; use
  `read_string_tag` when the tag is known to be a string.
- Program-scoped tag discovery is not exposed by the C#, Python, or C ABI
  wrappers; known program paths are fully usable for reads, writes, and
  batches regardless.

New in this release, documented rather than hidden:

- `get_tag_attributes`/`get_udt_definition`'s discovery-based fallback path
  does not report an accurate `TagAttributes.size` (the bulk discovery
  service doesn't carry it). Neither of the library's own internal callers
  needs that field, but a caller relying on it after hitting the fallback
  would get `0`.
- The simulator test harness has no CIP service `0x55` (Get Instance
  Attribute List) handler, so `discover_tags_detailed`/`discover_program_tags`
  cannot succeed against `SimulatedPlc` yet; the corresponding fallback path
  is proven on real hardware, not in the simulator suite.
