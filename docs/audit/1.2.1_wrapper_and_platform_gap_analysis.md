# 1.2.1 Wrapper and Native-Platform Gap Analysis

Date: 2026-08-21

Status: active preparation material for `1.2.1`; latest published release is
`1.2.0`.

## Summary

The Rust, C#, and Python paths have current user guides, package instructions,
automated tests, and real-controller evidence. C and C++ have a stable ABI,
checked-in header, CMake example, header/export parity check, simulator smoke,
and one complete real-hardware runner. The principal C/C++ gaps are packaging,
generated reference documentation, platform/compiler breadth, and the small
scope of the optional RAII convenience class—not missing CompactLogix or
ControlLogix protocol families in the Rust core.

## Native-Library Adoption Review

The review is limited to adoption and validation practices that fit this
project. Matching the protocol breadth of general-purpose industrial libraries
is not a goal here. This project remains deliberately focused on symbolic
EtherNet/IP access for Allen-Bradley CompactLogix and ControlLogix.

Practices already present here:

- a portable C ABI suitable for language wrappers;
- no OPC or RSLinx dependency;
- typed atomic access, arrays, raw/structured values, discovery, batch/MSP, and
  packet-size controls;
- examples, stable ABI metadata, capability discovery, explicit ownership/free
  functions, and actionable last-error text;
- Linux, Windows, and macOS native builds plus real-controller evidence.

Practices adopted for `1.2.1` documentation:

- a README release-target tier table that states exactly what is blocking;
- a separate exact processor/firmware/topology matrix;
- explicit invitations and a repeatable template for contributed hardware
  results;
- clear separation of supported low-level C ABI from the smaller example C++
  wrapper.

## Prioritized Gaps

| Priority | Gap | Why it matters | Suggested acceptance criterion |
|---|---|---|---|
| P0 | Honest C++ surface map | Users can mistake the small RAII example for the complete native API | Every guide states that the C ABI is complete and lists RAII coverage |
| P1 | Installable native SDK | Generic C/C++ consumers currently build Rust and manually locate the library | Release archive contains header/library/license; CMake config and `pkg-config` smoke in CI |
| P1 | Browsable C/C++ API reference | Header comments are useful but not searchable like docs.rs | Generated reference covers every exported function and ownership rule |
| P1 | RAII route and type coverage | Direct connect plus three types is insufficient for many routed Logix applications | Ordered routing and all atomic types covered with simulator tests |
| P2 | Compiler/sanitizer breadth | GCC/Clang/MSVC and sanitizer consumers catch integration defects Rust tests cannot | Named compiler matrix and ASan/UBSan native-consumer job pass |
| P2 | Endurance/performance automation | Existing field measurements are snapshots | Reproducible JSON/CSV output for the profiles in the hardware test program |

Completed during this review: macOS was added to the blocking C++ CI matrix,
including correct `.dylib` resolution, header/export parity, CMake build, and
simulator smoke coverage.

## Scope Decisions

- Do not add Modbus TCP, Micro800, PLC-5, or SLC support merely to match a
  broader third-party feature matrix.
- Do not label a whole Logix family `Done` from one catalog number and firmware.
- Do not call an operating-system CI pass hardware compatibility.
- Do not claim the header-only RAII example has feature parity with Rust, C#,
  or Python until its own surface and tests demonstrate it.
