# rust-ethernet-ip 1.2.1 Release Notes (Draft)

Status: preparing; not yet published

Latest published release: `1.2.0`

`1.2.1` is a backwards-compatible patch release collecting the fixes merged
after `v1.2.0` plus a substantial documentation, hardware-validation, and
project-website improvement. The Rust public API remains compatible. The C ABI
is coordinated at v3 because the new `eip_refresh_schema` symbol is additive;
all shipped wrappers pin the same ABI and expose the refresh operation.

## Code and Toolchain Changes Since 1.2.0

- Program-scoped Symbol Object discovery now continues after CIP `0x06`
  partial-transfer responses instead of losing programs with paged symbol
  tables.
- Program tag discovery now assigns the requested program scope to every
  returned tag. Both `Dashboard` and `Program:Dashboard` normalize to
  `TagScope::Program("Dashboard")`.
- The workspace MSRV is corrected from Rust 1.96 to Rust 1.88, verified against
  the locked dependency graph, workspace tests, and rustdoc.
- The desktop example now uses `egui`/`eframe 0.33.3` and `webbrowser 1.2.2`,
  removing `RUSTSEC-2026-0257` while preserving the Rust 1.88 baseline.
- C# batch writes now distinguish the program-scope separator in
  `Program:<program>.<tag>` from a UDT-member separator, so program-scoped
  scalar and array-element paths reach the native batch implementation.
- Repeated batch reads now cache both packed-BOOL and ordinary-array
  classifications per connection. The cache is shared across FFI client clones
  and scoped to a clone-shared schema generation. The new Rust
  `refresh_schema()` operation and route changes invalidate tag metadata, UDT
  definitions/templates/attributes, and array classifications together;
  generation guards prevent stale in-flight requests from refilling caches.
- Array reads now validate cached packed-BOOL addressing against controller
  responses. A stale read classification is evicted and rebuilt once, including
  inside a native batch without disturbing unrelated results. Write recovery
  remains fail-closed: a write is never replayed after an ambiguous outcome.
- Rust, C, C#, Python, and C++ now share an explicit schema-refresh workflow
  and expose the same schema/cache/recovery diagnostics. The additive native
  export is coordinated as C ABI v3 with a feature-detection capability bit.
- The [schema-change validation gate](../validation/2026-08-22_1756-L75_fw33_schema-change-gate.md)
  is offline-green across all bindings and hardware-validated on a live
  1756-L75 (firmware 33): array schema-swap (both directions, both scopes,
  all four bindings), UDT layout-edit/download with session-survival
  confirmed, and the post-schema full-coverage/batch regression, all PASS
  with zero anomalies.
- Python source checkouts now prefer an available release native library over
  a debug artifact.

## Documentation and Adoption

- Public API documentation now covers every item in `rust-ethernet-ip` and the
  `types`, `tag-path`, `protocol`, and `udt` support crates. A permanent
  `missing_docs` deny gate prevents regression.
- The new real-hardware compatibility matrix identifies exact CompactLogix and
  ControlLogix processors, firmware, routes, bindings, test dates, and source
  evidence without generalizing one result to a whole family.
- Contributors now have a safe test-controller setup, cross-binding functional
  procedure, 24-hour endurance profiles, performance metrics, and a standard
  validation-result template.
- A restore-safe four-language companion gate now measures batch operations,
  whole-UDT reads, controller discovery, and Rust program discovery separately
  from the full-tag inventory gate; unavailable wrapper surfaces are reported
  as `N/A`.
- The four full-coverage runners now include an explicit-write, release-build
  benchmark mode with per-call latency distributions and JSON output. A
  ControlLogix 1756-L75 firmware 33 through 1756-EN2T passed 27,648 measured
  reads and 27,420 measured writes across Rust, C#, Python, and C/C++ with zero
  failures.
- Batch characterization now covers logical sizes 1, 5, 10, 20, 50, and 100
  with robust outlier reporting and tags/second. On the L75 firmware 33,
  native size-100 DINT writes reached approximately 2,830 tags/second through
  Rust, C#, and C/C++; Python grouped writes remain clearly labeled as the
  sequential 1.2.x wrapper path.
- A controlled rerun on the same L75 target measured approximately 3,305
  size-100 DINT reads/second through Rust, C#, Python, and C/C++. For the
  build-identical Rust/C#/C++ comparisons, average read latency fell by
  90.8–91.4% and throughput improved by 10.9–11.6x; native writes remained near
  2,830 tags/second. The earlier result is retained as the before baseline.
- Active Markdown documentation is aligned around `1.2.0` as the latest
  published baseline and `1.2.1` as the next patch; historical validation
  records keep the versions they actually tested.
- The README now identifies Tier 1 blocking targets for Rust, C#, Python,
  C/C++, packages, and the real-PLC gate. Software-platform coverage remains
  explicitly separate from exact processor/firmware compatibility.
- A native-library adoption review added macOS to the blocking C++ matrix and
  records the remaining gaps: installable native SDK
  metadata/archives, generated API reference, broader RAII coverage, and
  compiler/sanitizer breadth.

## Project Website

The new static site in `website/` provides:

- a responsive, accessible light theme based on the existing Rust/industrial
  brand palette and repository logo;
- quick starts for Rust, C#, and Python;
- direct links to docs.rs, crates.io, NuGet, PyPI, GitHub source/releases, C#,
  Python, and C/C++ documentation;
- concise real-hardware proof points and a contributor call-to-action;
- dedicated privacy, license, industrial-safety, and security navigation;
- zero build dependencies and documented deployment to Cloudflare Pages or
  GitHub Pages.

The site intentionally links package registries at `1.2.0` until `1.2.1` is
published. Release-day preparation must update those package links and the hero
release badge.

## Compatibility and Validation Plan

- Run formatting, all-feature Clippy, full workspace tests, rustdoc with
  warnings denied, C# tests, Python tests, FFI header parity, and release
  readiness.
- Re-run the cross-binding real-hardware release gate when hardware is
  available because program-scoped discovery changed after `1.2.0`.
- Prefer adding at least one new firmware/model row or a 24-hour read soak, but
  do not block the patch solely on unavailable new hardware if the maintained
  5069-L330ERM fw38 release controller passes.

While `main` is the unpublished `1.2.1` development line, CI uses
`scripts/check-release-readiness 1.2.1 --development`. That mode requires the
1.2.1 machine metadata and development markers while allowing registry-facing
install snippets to remain truthfully pinned to published `1.2.0`. Release-day
checks intentionally omit `--development`.
