## Brief

### Goal

Land the small, independent, high-confidence fixes from the 2026-07-01 repository analysis ([`docs/agents/repo-analysis-2026-07-01.md`](../repo-analysis-2026-07-01.md), §6). Each is mechanical; they bundle because none warrants its own review cycle.

1. **semver gate is toothless** — `.github/workflows/ci.yml` runs `cargo semver-checks check-release --baseline-version 0.7.0`. A 0.x→1.x baseline permits any breaking change, so the gate catches nothing on the 1.x line. Re-point to `1.1.0`.
2. **`vergen` is a runtime dependency** — root `Cargo.toml` lists `vergen = "8.3"` under `[dependencies]` as well as `[build-dependencies]`; nothing under `src/` uses it at runtime (grep-verified). Every crates.io consumer compiles it for nothing. Remove from `[dependencies]`.
3. **`libc` unconditional** — only used in `src/ffi.rs` behind the `ffi` feature. Make it `optional = true` with `ffi = ["dep:libc"]`.
4. **Placeholder author email** — `authors = ["Sergio Gallegos <sergio@example.com>"]` is published crates.io metadata. Confirm the intended value with the maintainer (or drop the email, matching the sibling crates, which omit `authors` entirely — pick one convention for all five manifests).
5. **Release publish swallows all errors** — `release.yml`'s crates.io loop does `cargo publish -p "$crate" || echo "...continuing"`, tolerating auth/network/validation failures, not just already-published. Discriminate: continue only when the error output matches the "already exists" case; fail the job otherwise.
6. **No scheduled cargo-audit** — the audit job runs only on push/PR, so new RUSTSEC advisories against an idle `main` go unnoticed. Add a weekly `schedule:` trigger.
7. **Dead test files** — `tests/unit/element_addressing_tests.rs` is never compiled (cargo only builds top-level `tests/*.rs`; nothing `mod`-includes `tests/unit/`) and has diverged from its top-level twin. Delete the `tests/unit/` directory. Also delete `test_isolated/` at the repo root (single scratch `test_connection.cs` + csproj, referenced by nothing).
8. **`tests/release_readiness_tests.sh` not in CI** — the other three shell suites run in CI; wire this one into the same job.
9. **README overstates NuGet RIDs** — README claims the package bundles `osx-x64`; `release.yml` intentionally omits it (3 RIDs ship: win-x64, linux-x64, osx-arm64). Correct the claim (macOS-Intel restoration is ROADMAP item 3).
10. **CLAUDE.md FFI build command** — the build section says `cargo build --release` is what's needed for the C# FFI cdylib; without `--features ffi` that produces a cdylib with no `eip_*` exports (the exact cause of a past CI EntryPointNotFound incident). Fix the command and the sentence. (Full CLAUDE.md architecture refresh is ROADMAP item 1 — do *not* attempt it here.)
11. **NuGet csproj native-lib layout** — `csharp/RustEtherNetIp/RustEtherNetIp.csproj` includes the native library via OS-conditional `Content` items from `../../target/release/`, so a locally produced package lacks `runtimes/{rid}/native/` layout. Restructure to stage into `runtimes/{rid}/native/` so a local `dotnet pack` produces a package with correct (single-RID) native resolution. The multi-RID release pipeline must keep working unchanged.
