# 1.2.1 Release Validation Synthesis

## Summary

- `confirmed` shipped on 2026-08-22 (America/Denver).
- `confirmed` all five crates.io packages, NuGet `RustEtherNetIp` 1.2.1, and
  PyPI `rust-ethernet-ip` 1.2.1 are live.
- `confirmed` the tag-triggered GitHub Release workflow passed every build,
  publish, and manylinux smoke-test job.
- `confirmed` the post-publish main-branch CI fix is green and strict release
  readiness passes.
- `confirmed` registry-facing README/description content was captured before
  the post-publish documentation sweep and contains stale 1.2.0/current and
  1.2.1/not-published wording. Package code and version metadata are correct.
- `confirmed` source release-state lines are corrected, and generated Cargo,
  NuGet, wheel, and sdist documentation is now inspected before publication.

## Current Understanding

The release itself is operationally healthy:

- annotated tag `v1.2.1` resolves to commit `82d9160`;
- Release workflow run `32616381528` passed crates.io, NuGet, PyPI, Windows,
  macOS, manylinux build, and manylinux install-smoke jobs;
- Cargo downloaded the root 1.2.1 crate and resolved all four 1.2.1 support
  crates from crates.io;
- PyPI exposes Windows x64, macOS universal2, manylinux 2.28 x86-64 wheels and
  an sdist;
- NuGet exposes the .NET 10 assembly and native assets for win-x64, linux-x64,
  and osx-arm64;
- the four-language post-merge hardware gate and performance rerun passed on
  the 1756-L75/B firmware 33.011 with zero anomalies or operation failures.

The documentation sweep (`bf8156d`) and released-state CI correction
(`7ee4b20`) landed after the immutable release tag. Therefore the published
crate README still calls 1.2.0 current, while the NuGet README and PyPI long
description still show 1.2.0 install examples and say 1.2.1 is not published.
This is a packaging-documentation defect, not a binary, ABI, or registry
publication defect. Do not cut 1.2.2 solely to rewrite immutable descriptions.

On 2026-08-23, the remaining source release-state lines were corrected and the
release-readiness manifest was expanded to cover active documentation and all
three user install snippets. `scripts/check-packaged-release-docs` now reads
README/metadata content directly from `.crate`, `.nupkg`, wheel, and sdist
archives. CI inspects generated packages, and release jobs run the same check
before each registry upload. Version-neutral support-crate READMEs are scanned
for stale lifecycle claims; the root Cargo package, NuGet package, and Python
artifacts must also contain a recognized current-version marker.
