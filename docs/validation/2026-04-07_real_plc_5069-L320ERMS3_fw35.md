Observed documented PLC limitations:
- Direct writes to UDT array element members return CIP extended error `0x2107`.
- Direct writes to standalone STRING tags return CIP extended error `0x2107`.
- Direct writes to STRING members inside UDTs return CIP extended error `0x2107`.

Observed deviations vs simulator expectations:
- Prior to subscription hardening, `subscribe_to_tag("NonExistentTag")` returned success immediately and only failed inside the background poll loop. This was a library contract gap rather than a PLC-specific behavior difference. The implementation was updated during this validation to fail fast on the initial read.
- UDT reads for complete structures returned `symbol_id = 0` in the exercised examples, but member reads/writes and nested array access still worked on this controller for the tested scenarios.
- During the CompactLogix follow-up pass, native Multiple Service BOOL-array decoding was fixed for packed `0x00D3` responses, so mixed batch reads now handle controller BOOL array elements without wrapper fallback.

Benchmark interpretation:
- Batch reads on this PLC were substantially more efficient than repeated single reads for the same tag set.
- Batch writes also improved effective logical throughput versus single writes.
- Mixed batch reads now correctly include BOOL array elements on this CompactLogix target through the native path.
- These numbers are hardware-specific and should be treated as a field baseline for this controller/firmware/network path, not a universal product claim.
