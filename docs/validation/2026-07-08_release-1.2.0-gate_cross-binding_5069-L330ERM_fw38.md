## Scope

Official pre-publish hardware gate for the **1.2.0** release, run after the version bump and
the full pre-publish review. All four bindings (Rust, Python, C#, C/C++) drove the complete
read/write surface against a real controller, using an **extended manifest** that adds the
maintainer test program's custom-string members to the shared inventory.

- Controller: CompactLogix **5069-L330ERM**, firmware **38**, `192.168.0.101:44818`, slot 0.
- Native library: `rust_ethernet_ip.dll` built from `main` @ `d514123` with `--features ffi`
  (reports library version `1.2.0`, C ABI `2`). All four bindings loaded this artifact.
- Manifest: shared `examples/full_coverage_tags.json` (2304 tags) **plus** `Member6_String`
  (built-in `STRING`) and `Member7_String` (custom `Str400`) in all four UDT-member categories
  (controller/program × UDT/UDT-array) → **2338 total / 2319 writeable / 0 expected-blocked /
  19 read-only**. Member6/7 exist only on this maintainer test program, so the extension was
  passed via `--manifest`; the shared manifest is unchanged.

## Sequence (maintainer-monitored)

1. **Clear pass** — every writeable tag set to `0` / `0.0` / `false` / `""`
   (2319/2319 in 3.6 s, 0 failures; Python wrapper).
2. Per binding, the standard six phases: preflight inventory → read every tag → write random
   values → verify by read-back → blocked-probe (none expected) → settle to terminal state →
   settle-verify.
3. **Final state** left on the controller for visual inspection: DINT `999999`, INT `9999`,
   REAL `99`, BOOL `true`, all strings `"SETTLED"` (standalone STRINGs and Member5/6/7 in both
   scopes, UDT and array elements).

Build-order note: the Rust runner rebuild clobbers the FFI cdylib, so the `--features ffi`
rebuild was repeated before the Python/C#/C++ runs, per
[`docs/agents/notes/release-hardware-validation.md`](../agents/notes/release-hardware-validation.md).
